# 🧠 Transactions and Isolation Levels in PostgreSQL

Проект посвящён изучению транзакций, уровней изоляции и механизмов обеспечения согласованности данных в PostgreSQL.

В рамках выполнения заданий рассматриваются практические аспекты конкурентного доступа к данным: фиксация изменений, потеря обновлений, неповторяющееся чтение, фантомное чтение и взаимоблокировки.

Основная цель проекта — сформировать понимание того, как база данных обеспечивает целостность данных при одновременной работе нескольких пользователей и почему уровни изоляции являются одним из ключевых элементов ACID.

## ⚙️ Рекомендации к выполнению проекта

- Используй актуальную версию PostgreSQL
- Выполняй задания через командную строку `psql`
- Для большинства заданий потребуется два параллельных сеанса подключения к базе данных
- Перед началом работы убедись, что развёрнута предоставленная модель базы данных
- Внимательно соблюдай порядок действий между Session #1 и Session #2
- Фиксируй результаты работы с помощью скриншотов
- Проверяй текущий уровень изоляции перед выполнением экспериментов
- Анализируй причины появления аномалий и способы их предотвращения

## 🧪 Задание 00

Проверить видимость изменений между транзакциями.

### Session #1

- начать транзакцию
- изменить рейтинг пиццерии `Pizza Hut` на `5`
- убедиться, что изменение видно внутри текущей транзакции

### Session #2

- проверить, что изменение ещё не видно

### Session #1

- выполнить `COMMIT`

### Session #2

- убедиться, что после фиксации изменение стало доступно

## 🧪 Задание 01

Изучить аномалию **Lost Update (Потеря обновления)** на уровне изоляции `READ COMMITTED`.

Перед выполнением:

```sql
SHOW TRANSACTION ISOLATION LEVEL;
```

Должно быть:

```text
read committed
```

### Необходимо:

- открыть две параллельные транзакции
- прочитать рейтинг `Pizza Hut`
- в Session #1 изменить рейтинг на `4`
- в Session #2 изменить рейтинг на `3.6`
- выполнить действия в указанной последовательности
- проанализировать итоговое значение рейтинга

## 🧪 Задание 02

Повторить эксперимент с аномалией **Lost Update**, но использовать уровень изоляции:

```text
REPEATABLE READ
```

### Необходимо:

- открыть две транзакции
- прочитать рейтинг `Pizza Hut`
- в Session #1 обновить рейтинг до `4`
- в Session #2 обновить рейтинг до `3.6`
- сравнить результат с поведением на уровне `READ COMMITTED`

## 🧪 Задание 03

Изучить аномалию **Non-Repeatable Read (Неповторяющееся чтение)** на уровне изоляции:

```text

```

### Session #1

- прочитать рейтинг `Pizza Hut`

### Session #2

- выполнить `COMMIT`

### Session #1

- повторно прочитать рейтинг в рамках той же транзакции
- сравнить результаты первого и второго чтения

## 🧪 Задание 05

Изучить аномалию **Phantom Read (Фантомное чтение)** на уровне:

```text
READ COMMITTED
```

### Session #1

В одной транзакции:

- вычислить сумму всех рейтингов пиццерий

### Session #2

- добавить новую запись:

```text
id = 10
name = 'Kazan Pizza'
rating = 5
```

- выполнить `COMMIT`

### Session #1

- повторно вычислить сумму рейтингов
- сравнить результаты

## 🧪 Задание 07

Воспроизвести ситуацию **Deadlock (Взаимоблокировка)**.

### Необходимо:

- использовать два параллельных сеанса
- выполнить любые SQL-запросы к таблице `pizzeria`
- создать ситуацию, при которой:

  - Session #1 ожидает ресурс, удерживаемый Session #2
  - Session #2 ожидает ресурс, удерживаемый Session #1

- добиться возникновения ошибки взаимоблокировки (`deadlock detected`)

## 🧠 Итог

Проект помогает понять внутренние механизмы работы транзакций и уровней изоляции в PostgreSQL.

После выполнения заданий формируется понимание:

- принципов ACID
- работы COMMIT и ROLLBACK
- причин возникновения аномалий данных
- различий между уровнями изоляции
- механизмов блокировок и взаимоблокировок

Полученные знания являются фундаментом для разработки надёжных backend-приложений, финансовых систем и высоконагруженных сервисов, где критически важна согласованность данных.
