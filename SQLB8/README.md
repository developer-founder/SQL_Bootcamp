# 🧠 Let's Improve Customer Experience

Проект посвящён изучению механизмов обеспечения целостности данных, реализации бизнес-логики и оптимизации структуры базы данных в PostgreSQL.

В рамках выполнения заданий рассматриваются создание новых сущностей, работа с ограничениями, индексами, последовательностями, автоматизация генерации первичных ключей, управление качеством данных и реализация системы персональных скидок.

Основная цель проекта — сформировать понимание того, как проектируются и поддерживаются базы данных в production-среде с учётом бизнес-требований, производительности и согласованности данных.

* Используй актуальную версию PostgreSQL

## 🧩 Структура базы данных

Проект основан на реляционной модели, включающей:

* **person** — пользователи системы
* **pizzeria** — список пиццерий
* **menu** — меню и цены
* **person_visits** — посещения пиццерий
* **person_order** — заказы пользователей

Связи между таблицами заданы явно через первичные и внешние ключи.

---

## 🧪 Задание 00

Реализовать систему персональных скидок.

Создать новую таблицу:

**person_discounts**

Требования:

* добавить первичный ключ `id`
* создать внешний ключ `person_id` на таблицу `person`
* создать внешний ключ `pizzeria_id` на таблицу `pizzeria`
* использовать явные имена ограничений внешних ключей
* добавить поле `discount`
* использовать тип данных `numeric` для хранения процентов скидки

---

## 🧪 Задание 01

Заполнить таблицу персональных скидок на основе истории заказов.

Требования:

* сгруппировать данные по `person_id` и `pizzeria_id`
* вычислить размер скидки в зависимости от количества заказов

Правила расчёта:

* 1 заказ → 10.5%
* 2 заказа → 22%
* 3 и более заказов → 30%

Для генерации идентификаторов использовать:

`ROW_NUMBER() OVER ()`

---

## 🧪 Задание 02

Построить отчёт по заказам с учётом персональных скидок.

Получить:

* имя клиента
* название пиццы
* исходную стоимость
* стоимость со скидкой
* название пиццерии

Отсортировать результат по имени клиента и названию пиццы.

---

## 🧪 Задание 03

Повысить производительность и обеспечить уникальность данных.

Создать уникальный многоколоночный индекс:

`idx_person_discounts_unique`

Для столбцов:

* person_id
* pizzeria_id

Подтвердить использование индекса через `EXPLAIN ANALYZE`.

---

## 🧪 Задание 04

Добавить ограничения целостности данных для таблицы `person_discounts`.

Требования:

* запретить NULL в `person_id`
* запретить NULL в `pizzeria_id`
* запретить NULL в `discount`
* установить значение по умолчанию 0
* ограничить диапазон скидки значениями от 0 до 100

Использовать именованные ограничения.

---

## 🧪 Задание 05

Реализовать правила Data Governance.

Добавить комментарии:

* для таблицы `person_discounts`
* для всех столбцов таблицы

Комментарии должны описывать назначение данных и их бизнес-смысл.

---

## 🧪 Задание 06

Автоматизировать генерацию первичных ключей.

Требования:

* создать последовательность `seq_person_discounts`
* настроить автоматическую генерацию значения `id`
* установить корректное начальное значение последовательности

Следующее значение последовательности должно рассчитываться как:

`количество записей в person_discounts + 1`

Использование жёстко заданных значений запрещено.
